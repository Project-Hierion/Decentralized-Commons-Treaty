# Amendment Process

---

## Overview

The Treaty is a living document. Amendments allow it to evolve with the community's needs while protecting its core principles.

---

## Process

### 1. Proposal
- Any active participant may propose an amendment.
- Proposal must be in writing (PR to this repository).
- Proposal must include:
  - The specific text to be changed
  - Rationale for the change
  - Impact assessment (how it affects signatories)

### 2. Comment Period
- Minimum **6 months** open for public comment.
- Comments may be submitted via GitHub Issues, PR discussion, or public forums.
- The Steward ensures the comment period is announced widely.

### 3. Revision
- The proposer may revise the amendment based on feedback.
- Revised versions restart the comment period (at proposer's discretion).

### 4. Ratification
- Amendment is ratified by **rough consensus** of active participants.
- Sustained opposition blocks ratification.
- Mere disagreement does not block—only active, reasoned opposition.

### 5. Implementation
- Upon ratification, the Steward updates the Treaty.
- Amendment is recorded in the repository's history.

---

## Limitations

No amendment may violate the core principles of:

- Interoperability
- Interest-Neutral Stewardship
- Forkability
- People Governance
